# aps-engine

独立 Java 17 APS 自动排产类库。提供工艺路线展开、正向/逆向有限产能排产、班次、资源占用和工序间隔计算，不连接数据库，也不依赖 Spring。

## 构建

```bash
mvn clean package
```

## 使用入口

```java
ApsEngine engine = ApsEngines.createDefault();
ApsResult result = engine.schedule(request);
```

依赖坐标（发布到 Maven Central 后可用）：

```xml
<dependency>
    <groupId>io.github.ljyz</groupId>
    <artifactId>aps-engine</artifactId>
    <version>0.2.4</version>
</dependency>
```

调用方负责提供排产数据并保存结果；引擎本身不访问数据库。


## 百分制评分（算法2.1.1）

评分统一采用三个归一化指标：

- `达成率 = 完整排入的拆分工单数 / 全部待排拆分工单数 × 100`。
- `准交率 = 按交期完成的拆分工单数 / 全部待排拆分工单数 × 100`；未排工单不能提高准交率。
- `完成时间得分 = 100 × W / (W + E)`。固定基准 `B = max(currentTime, 全部任务最早允许开始时间)`，`W = max(1秒, 全部任务最晚交期 - B)`，`E = max(0秒, 方案最终完成时间 - B)`。包含等待和休息，使用秒级时间；不随候选开始时间、额外排班或延期范围改变。超过交期后仍平滑下降，避免晚完方案全部归零。

`综合评分 = (完成时间得分 × finishTimeWeight + 达成率 × achievementRateWeight + 准交率 × onTimeDeliveryWeight) / 三个权重之和`。

三个权重相同时各占三分之一，按相同比例扩大权重不改变得分。权重0表示禁用该项，负数按0处理；三个权重全0时回退为1:1:1。引擎搜索及候选排序保留12位小数，后端仅在展示时保留两位，不重复归一化，展示同分时仍保留引擎排序。无待排工单或没有完整排入工单时得分为0，所有对外评分均在0～100之间。例如时间得分50、达成率100、准交率50、权重1:1:1，综合评分66.67。

硬约束优先：完整可执行方案始终优先于不完整方案；不完整方案也按相同指标引导搜索，但不作为可保存候选返回。因此所有返回的完整候选达成率均为100，该项主要引导搜索阶段改善排入数量。已保存的历史日志保持原评分，新算法不重算历史记录。


### 候选去重与同分推荐

候选以实际排法去重：比较来源计划、拆分工单、数量、各工序起止时间和工时、实际资源与占用容量、工作时间段。候选ID、临时单号、资源名称和列表顺序不作为差异；数量与容量忽略小数位格式差异。即使关闭资源时间线输出，仍在隐藏字段前完成去重，不能误合并使用不同资源的方案。

排序先比较引擎保留12位精度的综合评分，综合分相同时，比较各拆分工单从本次请求固定时间基准到其实际完成的累计秒数，累计值越小越优。基准为 `max(currentTime, 全部任务最早允许开始时间)`，包括等待和休息。该规则统一用于遗传锦标赛、精英保留、候选档案、收敛判断和最终推荐；同分累计耗时改善也会重置停滞代数。

`candidateLimit` 是去重后的数量上限，算法仅找到两种排法时返回两个候选，不用重复方案补满数量。遗传候选档案先去重再按上限截断，推荐方案固定为第一项。综合分和累计耗时都相同的不同排法仍可保留，并按本次搜索的稳定顺序返回。界面四舍五入同分时，仍优先按引擎完整精度排序。历史日志保持原内容，新规则仅作用于重新计算的结果。
